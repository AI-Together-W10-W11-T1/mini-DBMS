## 승인과 구현

사용자 A/A/A 선택으로 자동 ID는 현재 존재하는 최댓값+1, ID의 값은 메모리 행 번호, 진행 순서는 독립 트리 → 엔진 통합 → 100만 건 비교로 정했다. 빈 테이블 자동 ID는1이며 최댓값 삭제 후 재사용과 INT64_MAX 도달 처리는 후속 통합에서 구현한다. ID는 기본키 역할의 레코드 ID다. 이후 용량 A와 첫 범위 A를 승인했다. 선택 출처와 정확한 범위는 [계약 JSON](../../.cache/m9/contract.json)을 따른다.

이번 증분은 src/bptree.c·h와 테스트·CMake·검사 어댑터의 독립 트리다. production 최대 자식32·구분키31·리프31, 작은 시험 구성 자식4·리프3으로 같은 알고리즘을 실행한다. 용량은 초기 설계값이며 성능은 미측정이다.

- 양수 INT64 키와 size_t 행 번호를 복사하고 삽입·정확 검색·중복 거절·lower_bound·순방향 순회·해제를 제공한다. 행 번호0과 SIZE_MAX를 모두 지원한다.
- 구분키는 오른쪽 서브트리의 최소 키다. 리프·내부·루트 분할 후 점유율과 균일 깊이를 유지하고 리프 연결로 정렬 순회를 이어간다.
- 분할 형제와 새 루트를 변경 전에 모두 할당한다. 실패하면 임시 노드를 정리하고 기존 키·값·연결·커서를 보존해 재시도한다. 중복·잘못된 키·자원 실패 결과를 구분한다.
- 트리는 노드를 소유한다. 성공한 변경과 해제는 커서를 무효화한다. 개수와 경로 상한을 검사하며 양수 INT64 키와 최소 분기에서 높이64 미만을 설명한다.

## 실제 실행과 근거

- 실제 Red는 configure/build 성공 후 CTest 실패4개, 종료8이었다. 빌드 가능한 미구현 stub이 첫 삽입에서 NOMEM을 반환했다. 분할·범위·fault의 깊은 경로는 전제 삽입에서 실패해 초기 Red의 도달 범위가 제한됐다.
- 작성자는 부분12/12 후 새 configure/build/전체 CTest135/135를 통과했다. production 비계측 객체는 감소20000키 삽입·검색·전체 순회와 중복·잘못된 입력·반복 해제를 실행했고 llvm-nm으로 시험 심볼 부재를 확인했다. [작성자 결과](../../.cache/m9/implementer-result.json)·[production 근거](../../.cache/m9/production-symbol-check.json)
- 독립 Reviewer_QA는 고정 소스에서 자신의 새 configure/build/전체 CTest135/135를 통과했다. 별도 sorted-array probe가 구성4와32 각각 sparse/extreme20000키, 실제 할당 위치별 실패·재시도, 노드 바이트·커서·매핑·깊이·점유율·연결을 확인했다. 최대 사전 할당 노드는 각각10과4였다. 코드 검토 APPROVED, 실행 PASS이며 차단 지적은 없다. [독립 결과](../../.cache/m9/reviewer-result.json)
- 양쪽 전체 회귀의 고정 소스 digest는 `031513298e59816cd4f2ef8a4f4122d0f5849d4f8005fb58359f89e06e9c652b`다. 실행 시간·로그·보고서 해시는 [독립 명령 영수증](../../.cache/agent-harness/m9-native-20261118/commands/4-regression/receipt.json)과 작성자 결과의 근거 참조에 둔다.
- 사용자가 바빠 QA를 넘기자는 최신 지시를 주어 이미 완료한 독립 근거를 보존하고 추가 QA를 중단했다. 이 지시는 이번 추가 검사 중단에 적용하며 M9는 이후 사용자 완료 승인·정상 하네스 DONE을 확인했다.
